Authway Zitadel v4.16.1 SSO Multi-App Draft · 2026-08-06

SSO đa app qua Zitadel + Zimbra LDAP

Kiến trúc login end-to-end cho toàn bộ app phòng KT (OneLog, OneMCP, vibecode apps). Đăng nhập 1 lần bằng email Zimbra → dùng tất cả app.

1 · Big picture

Nhân viên KT có 1 tài khoản email Zimbra duy nhất. Login lần đầu vào bất kỳ app nào → Zitadel redirect qua form LDAP → bind Zimbra → session cookie share cross-app trong .inet.vn domain → truy cập mọi app khác không phải login lại.

2 · User journey — login lần đầu

Từ góc nhìn của user KT. Ví dụ user Hoan Dat mở OneMCP lần đầu:

Step 1

Hoan Dat gõ https://onemcp.inet.vn vào browser.

Step 2

Traefik chặn request, gọi oauth2-proxy hỏi "user này đã login chưa?". Chưa → redirect user qua https://iap.inet.vn/oauth2/start.

Step 3

oauth2-proxy khởi tạo OIDC flow, redirect user qua https://auth.inet.vn/ui/v2/login (Zitadel).

Step 4

Zitadel hiện login page với button "Zimbra Mail". Hoan Dat click.

Step 5

Zitadel hiện LDAP form. Hoan Dat nhập hoandat@zimbra8815.inet.name.vn + password Zimbra.

Step 6

Zitadel bind vào Zimbra LDAP với credentials đó qua LDAPS :636. Zimbra return "OK" nếu đúng password.

Step 7

Zitadel tự động tạo user (auto-provision) với attrs: email, họ tên từ Zimbra. Nếu là lần đầu, prompt setup MFA (OTP). Từ lần 2 → chỉ login + OTP.

Step 8

Zitadel issue OIDC token → callback về oauth2-proxy → set cookie session cho domain .inet.vn.

Step 9

Redirect user về https://onemcp.inet.vn. Traefik forward request kèm header X-Auth-Request-Email: hoandat@zimbra8815.inet.name.vn. OneMCP đọc header → biết ai đang login.

SSO benefit

Ngay sau đó, Hoan Dat mở tab mới https://onelog.inet.vn → không phải login lại. Cookie .inet.vn share cross-subdomain. Traefik forward luôn header email → OneLog nhận diện user.

3 · Dev journey — onboard app mới (vibecode)

Dev KT có 1 app mới cần bảo vệ SSO. Không cần code auth. 3 bước:

1 Deploy app

Container app join network edge của Traefik. Không expose port public.

myapp:
  image: myorg/myapp:latest
  networks: [edge]
2 Traefik labels

Thêm 3 label vào compose để Traefik route + auth.

labels:
  - "traefik.enable=true"
  - "traefik.http.routers.myapp.rule=Host(`myapp.inet.vn`)"
  - "traefik.http.routers.myapp.middlewares=iap-auth@file"
3 Đọc user email

Backend đọc header. 15 dòng code cho Node/Python/Go.

// Node.js Express
app.use((req, res, next) => {
  req.userEmail = req.header('X-Auth-Request-Email');
  next();
});
Effort

Onboard app mới < 15 phút. Không cần OIDC client library, không cần setup callback URL, không cần lưu client_secret trong app. Toàn bộ auth phức tạp handle ở IAP layer.

5 · LDAP flow bên trong Zitadel

Chi tiết Zitadel gọi Zimbra LDAP ra sao khi user submit form:

(nếu chưa có) Z-->>U: OIDC token else password sai L-->>Z: Invalid credentials (49) Z-->>U: "Invalid credentials" end
Attribute mapping
  • ID: mail (unique cross-domain)
  • Username / Email: mail
  • First Name: cn (Zimbra không có givenName mặc định)
  • Last Name: sn
  • Display Name: cn
Search config
  • Base DN: dc=vn (cross-domain broad)
  • User filter: mail
  • Object classes: inetOrgPerson, zimbraAccount
  • Timeout: 5s
  • Options: auto-create + auto-update ON

7 · FAQ

❓ Nếu user đổi password trên Zimbra thì sao?

Session Zitadel hiện tại vẫn valid tới khi cookie expire (7d). Sau đó lần login mới, Zitadel bind Zimbra với password mới → OK. Không phải update gì ở Zitadel.

❓ Zimbra down có ảnh hưởng SSO không?

User đang trong session (7 ngày) → OK. User mới login trong lúc Zimbra down → fail (không bind được). Recovery: Zitadel local admin account bypass để login vào console + emergency ops.

❓ Logout thì sao?

User click "Logout" bất kỳ app → oauth2-proxy clear cookie + gọi Zitadel end_session → logout toàn bộ apps.

❓ User ngoài KT (khách, đối tác) login được không?

Không, hiện tại chỉ user có tài khoản Zimbra KT. Muốn support user ngoài → thêm IdP thứ 2 (Google OAuth hoặc local Zitadel user) — defer feature request tương lai.

❓ App cần API-only (curl, script) auth thì sao?

IAP browser-based. Cho API/mobile, app tự implement OIDC-native với Zitadel (opt-in). Ví dụ: OneMCP MCP endpoint cho AI client dùng bearer token flow riêng.

❓ Add domain Zimbra mới thì sao?

Nếu domain nằm trong Base DN hiện tại (dc=vn) → auto-work, không cần đổi Zitadel. Nếu ngoài (VD .com) → mở rộng Base DN trong Zitadel IdP config.
